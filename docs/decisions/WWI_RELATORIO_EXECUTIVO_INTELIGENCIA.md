## 2. Arquitetura implementada (Fase A)

- **`src/relatorio/coletar-dados-relatorio.js`** (ampliado, não reescrito) — `SECOES_RELATORIO_FECHAMENTO` cresceu de 6 pra 15 títulos, cada um conferido contra o HTML real antes de adicionar (nenhum título hardcoded por suposição). Ganhou um 3º extrator (`_extrairLinhasRotulosInline`) pro formato "rótulo em `<div style="color:var(--text-mid)">` seguido de `.v` irmão", usado por Meta do Milhão/Passivos/Consórcio Casa Nova/Reserva de Emergência — os 3 extratores agora rodam sempre e a UNIÃO dos resultados vira `linhas` (antes era só fallback sequencial), porque várias seções novas combinam mais de um formato no mesmo bloco. Retorno ganhou o campo `competencia` (a chave real do ciclo, `VARS.cicloAtual`, distinta do texto de exibição `cicloAtual`).
- **`src/relatorio/gerar-analise-financeira.js`** (novo) — `calcularIndicadoresEScores(dados)` computa o Wealth Score (0-100, média ponderada de 7 sub-scores, pesos redistribuídos entre os que têm dado quando algum falta — nunca trata "sem dado" como zero) + 4 índices dedicados (Meta do Milhão, Casa Nova, Independência Financeira, Disciplina Financeira). `gerarAnaliseFinanceira(dados)` gera a narrativa (pontos fortes/fracos, riscos, oportunidades, recomendações, parecer final) por regras condicionais sobre os números já coletados — nenhuma frase carrega um valor que não veio de `dados`. `compararComHistorico(indicadores, historico)` produz as frases de evolução (ciclo anterior, janelas de 3/6/12) e degrada silenciosamente sem histórico (1º relatório da série). `wwiBuscarHistoricoRelatorios(competencia)` lê `historico_relatorios` (leitura pública, mesma régua de RLS do resto do sistema) — nunca escreve.
- **`index.html`** — `gerarRelatorioFechamentoPDF()` reescrito pra: coletar dados → calcular indicadores → buscar histórico → reutilizar `analise_ia` já salva se a competência já existe, ou gerar narrativa na hora só pra exibir (sem persistir) se ainda não existe → montar comparativo → desenhar o PDF. `gerarPdfRelatorioFechamento()` ganhou blocos novos (Wealth Score em destaque, Resumo do CFO, Pontos Fortes/Fracos, Evolução Patrimonial, Oportunidades de Crescimento, Matriz de Riscos, Parecer Final) via helper `pdfDesenharBlocoTexto()` reaproveitando o mesmo estilo visual dos cards de seção já existentes — nenhum bloco vazio é desenhado (narrativa ausente = seção omitida, nunca um card "sem dados" pra texto).
- **`supabase/migrations/20260814070000_historico_relatorios_wwi.sql`** (escrita, **NÃO aplicada**) — tabela `historico_relatorios` (PK `competencia`, `dados_json`/`analise_ia` JSONB separados de propósito — só assim dá pra sobrescrever números preservando narrativa no mesmo `UPDATE`) + RPC `wwi_upsert_relatorio_mensal` (`SECURITY DEFINER`, sem `GRANT` a `anon`/`authenticated`, só chamável com `service_role`).

## 3. Por que motor de regras em vez de LLM (justificativa completa)

1. Não existe hoje, em nenhum lugar do código (`app.js`, `index.html`, `.github/workflows/*`, `scripts/sync/*.py`), nenhuma integração com API de LLM (OpenAI/Anthropic/etc) em produção — adicionar essa dependência sem pedido explícito abriria uma chave de API nova, custo recorrente e uma superfície de falha de rede numa feature que deveria ser "gerar um PDF a partir de dado já calculado".
2. Um LLM real geraria texto não-determinístico sobre dado financeiro pessoal sensível — risco real de alucinar um número que não bate com o card real, exatamente o tipo de bug que este projeto trata como inaceitável (ver comentário de `coletar-dados-relatorio.js`: "fonte única... nunca pode dessincronizar").
3. O padrão dominante do projeto inteiro é "ler o que já foi calculado, nunca reimplementar/reinterpretar por conta própria" — um motor de templates que monta frases a partir de comparações determinísticas é a extensão natural desse padrão, não uma ruptura.
4. Se no futuro for desejado um LLM real (variar tom da narrativa, resumir texto livre), isso vira uma Fase 2 opcional isolada — o motor de regras continua como base/fallback, e qualquer texto gerado por LLM ainda seria ancorado nos mesmos números (o LLM reescreveria estilo, nunca inventaria valor).

Pesos do Wealth Score: Liquidez 15% · Proteção Patrimonial 15% · Investimentos 20% · Endividamento 15% · Organização Financeira 10% · Execução de Metas 15% · Construção Patrimonial 10%. Fórmula exata de cada sub-score e dos 4 índices dedicados está comentada linha a linha em `src/relatorio/gerar-analise-financeira.js` (função `calcularIndicadoresEScores`) — não duplicada aqui pra evitar as duas fontes divergirem no futuro.

**Limitação conhecida, documentada no próprio código**: "Organização Financeira" é hoje um proxy de completude do próprio relatório (% de seções que o coletor conseguiu extrair), não uma medida de categorização/auditoria de transação — esse dado não está disponível pro coletor de DOM. Se o usuário quiser um score de organização mais fiel, precisa de uma fonte nova (ex. RPC que exponha `% transações categorizadas`, hoje só consultável via SQL direto).

## 7. Achado real do primeiro Test Run (14/08/2026) — bug de conversão de percentual

Usuário disparou "Test Run" real no cronjob recém-criado. Rodou de ponta a ponta (heartbeat `sucesso`, snapshot gravado em `historico_relatorios` pra competência `2026-07`), mas conferindo o resultado célula a célula (nunca aceitar número de automação nova sem checar contra o dado real) achei: `indicadoresBrutos.consorcioCasaPagoPct` gravou `42`, quando o valor real é `0,42%` (mesmo número já citado no Tactical Wealth Report anterior — "0,42% pago").

**Causa raiz**: `wwi_gerar_relatorio_mensal.py` tinha uma heurística (`*100 se valor <= 1`) pra converter fração 0-1 em percentual — mas `vw_patrimonio_v2.consorcio_casa_pago_pct` **já devolve o percentual pronto** (confirmado comparando com `consorcio_auto_pago_pct = 75.22`, que também já é literal, nunca fracionário). A heurística só quebra quando o percentual real É pequeno (<1%) — exatamente o caso real do Consórcio Casa Nova agora, então o bug não aparecia em nenhum teste anterior com dado fake.

**Correção**: heurística removida (linha lida direto, sem transformação). Linha já gravada corrigida via `wwi_upsert_relatorio_mensal` chamada direto por SQL com os valores certos (`score` recalculado de 58 para 53, já que `execucaoDeMetas` também dependia do valor errado) — `created_at` preservado, `analise_ia` preservada (nenhuma frase da narrativa citava esse número, então o texto já gerado continuou válido). Commit `0886352`.
